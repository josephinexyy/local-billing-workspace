# 验证记录

日期：2026-11-13。对象：公开发布版，全部测试采用虚构数据。持续集成结果见 [GitHub Actions](https://github.com/josephinexyy/local-billing-workspace/actions)。

## 业务与存储检查

- `npm run check`：脚本引用、JavaScript 语法、示例 JSON、字体及 OCR 文件完整性。
- `npm run format:check`：统一自有源码格式，第三方库保持原样。
- `npm test`：53项检查。
- `npm run build`：离线文件可重新生成；CI 比对构建结果与提交内容一致。

测试直接导入 CommonJS 导出，不再按字符串位置截取应用源码。覆盖精确金额、年度编号、重复与冲突、无效日期、模板转义、签发方快照独立性、设置变化、v1/v2兼容、v3完整性、导入前留底、保存失败、两份存储实例的同时写入与重复收款。

同号且签发方资料不同会阻止合并；不完整快照不会用演示默认资料自动补齐。旧记录按升级时可取得资料留底，并标记来源。

## 实际浏览器回归

命令：`npm run test:browser`。Node 测试启动随机端口的本机静态服务、真实 Chromium 和隔离浏览器上下文，使用页面表单与下载功能。当前共11个场景，最终通过情况以本次提交的 Actions 结果为准。

| 场景 | 验证方式 |
| --- | --- |
| 新建 PI → 确认到账 → INV / RC | 操作表单，核对状态、编号、金额；下载并解析单张 PDF 与 ZIP 内两个 PDF |
| 甲公司开单后改乙公司 | 比较旧 PI 票面；核对 INV / RC 的抬头与签署人；新业务使用乙公司 |
| 快速重复提交收款 | 同一事件轮两次提交表单，只生成一组 INV / RC |
| 备份恢复到空浏览器 | 比较全部业务、客户、币种、公司设置和签发方快照；下载导入前备份 |
| 两标签页同时开单 | 真实共享 localStorage，两个表单同时提交；记录均保留且 PI / 合同编号唯一 |
| 两标签页确认同笔收款 | 同时提交，只保留一组 INV / RC |
| 长名称、地址和服务描述 | 下载多页 A4 PDF；核对每页图像宽高、全部栅格行连续保留及页边界范围 |
| 旧账本升级再修改设置 | 旧记录保持甲公司并显示来源提示；升级前原始 JSON 可下载 |
| 单文件 HTTP 运行 | 加载自包含 HTML，真实表单创建带公司快照的业务 |
| 单文件直接打开 | 通过 file:// 运行自包含文件，验证开单和公司快照 |
| 演示隔离 | 演示开单及重置后，正式账本内容保持一致 |

PDF 文字当前由页面栅格化生成。分页检查覆盖所列长内容样例及文字行边界，不代表验证了所有长度、字体或浏览器排版，也不代表 PDF 具有可搜索文本。

本地执行环境限制独立 Chromium 启动，因此完整浏览器套件在 GitHub Actions 隔离环境执行。旧版单张与成对 PDF、收款、公司设置迁移和一张清晰虚构 OCR 图片曾经由人工浏览器操作验证；本次自动套件不包含 OCR 准确率评估。

## 历史内存基准

[backup-benchmark.json](results/backup-benchmark.json) 保留早期100条虚构记录的 v2 恢复路径测量，仅作该次运行记录。新增快照和校验后，不能将旧数值当作本版性能结论。

可用 `node scripts/benchmark.cjs` 重新生成当前版本的内存测量；这不包含存储、用户输入、界面、OCR或PDF，也没有人工任务基线。

## 未覆盖与限制

Firefox、Safari、手机及不同操作系统的完整矩阵；极端超长内容；浏览器清理和长期磁盘故障；旧版页面与新版同时操作；模糊图片与多种商证版式；真实用户效率对照及长期可靠性。当前没有团队并发、服务端审计或银行自动对账能力。Web Locks 仅协调同一来源且遵守本版协议的页面。
